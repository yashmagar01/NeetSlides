PHASE 1 — Core PDF Parsing Engine (Weeks 1–2)
🎯 Objective

Extract high-quality structural data from AI-generated PDFs.

This is the most critical phase. Everything else depends on it.

Scope

PDF ingestion

Text extraction with coordinates, font size, font name

Page-wise processing

Technical Direction (from research)

Language: Python

PDF library: pdfplumber

Chosen for MIT license + geometric access

Reject PyMuPDF (AGPL risk)

Treat each page as one slide

Deliverables

parser.py

Extract characters → lines → blocks

Preserve:

text

x0 / top / bottom

font size

font name

JSON-like intermediate representation per slide

Example (conceptual):

{
  "slide_3": {
    "elements": [
      { "text": "Introduction", "font_size": 32, "x": 120, "y": 80 },
      { "text": "• AI in Education", "font_size": 18, "x": 140, "y": 160 }
    ]
  }
}

Exit Criteria

Parser reliably extracts text + layout metadata

No images-only output

Reproducible results across multiple PDFs

If text quality is bad → do not proceed.

PHASE 2 — Semantic Heuristics Engine (Weeks 3–4)
🎯 Objective

Convert raw PDF data into semantic meaning.

This is where your tool becomes different.

Scope

Title detection

Body text detection

Bullet hierarchy detection

Noise removal (headers, footers)

Heuristics (directly from your research)

Font Histogram Method

Largest font → presentation title

Second largest → slide title

Most frequent → body text

Spatial Rules

Upper quadrant + large font → title

x-indentation → bullet level

Vertical spacing → paragraph vs new bullet

Artifact Filtering

Repeated text at same coordinates across slides

Remove “Generated by …”, page numbers, footers

Deliverables

layout_analyzer.py

StyleMap generator

Clean semantic model per slide:

{
  "title": "AI in Education",
  "bullets": [
    { "level": 0, "text": "Context-aware tutors" },
    { "level": 1, "text": "NotebookLM" }
  ]
}

Exit Criteria

Titles are correct ≥80% of time

Bullet nesting matches visual intent

Noise does not pollute slide body

This phase defines credibility.

PHASE 3 — PPTX Reconstruction Engine (Weeks 5–6)
🎯 Objective

Generate truly editable PowerPoint files, not fake ones.

Scope

PPTX generation

Placeholder-based slide creation

Font normalization

Technical Direction

Library: python-pptx

Use placeholders, not absolute text boxes

Title → Title placeholder

Bullets → Body placeholder

Key Rules

No hard-coded coordinates

Respect PowerPoint’s layout engine

Enable theme reflow

Deliverables

generator.py

PPTX output with:

Editable titles

Editable bullets

Correct indentation levels

Default academic font fallback

Exit Criteria

User can:

Change theme

Change font

Edit text

Slide does NOT break visually after theme change

If theme breaks → implementation is wrong.
